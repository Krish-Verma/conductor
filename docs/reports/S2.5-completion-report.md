## Positive controls — the thing this slice exists to get right

S0's first containment round was invalid **twice, both failing permissive**: the
"outside" directory was itself under `/tmp` (which the policy permits), and the AF_UNIX
test failed on `sun_path` length rather than on the sandbox. S2.5's central requirement
was to make that class of error impossible.

| Denial-based probe | Positive control | Status |
|---|---|---|
| write outside: sibling, `$HOME` root, `/Users/Shared`, nested `sh -c` | unlaunched run → allowed | ✅ |
| TCP connect, DNS resolve | unlaunched run → allowed | ✅ |
| AF_UNIX connect | **`--allow-unix-socket` → allowed** | ✅ strongest form (M11): launcher held constant, only the permission varies |

**Every denial-based probe has one.** Structurally, `CaseReport::new` **cannot produce
`Denied` without a successful control** — a blocked operation whose control is missing or
failed becomes `Broken`. Permitted operations (`/tmp` write, planted-secret read,
in-workspace write) need no control: they are proof by success.

Three whole-instrument controls also run: the payload self-check unlaunched, launcher
liveness (`exit 42` propagates — M15), and a socket self-connect before any agent is
involved.

I verified the mutation evidence the subagent reported: asserting `credential_read ==
Hard` (which M12 says is false) fails with `left: None, right: Hard`, so the assertion is
live rather than vacuous.

## How `tool_interception` is prevented from gating

Three **type-level** barriers, not comments:

1. stored as `Informational`, which has **no `PartialOrd`** — it cannot be compared to a
   requirement;
2. `Informational` exposes **no accessor returning `Enforcement`** — it cannot be
   unwrapped into something comparable (only `label() -> &str`);
3. `GatingDimension` — the only thing an eligibility check can iterate — **has no variant
   for it**.

Proven by three `compile_fail` doctests, plus a **non-vacuity control doctest** that
exercises every path, field and method the failing three use, so they can only be failing
on the operator itself. That control is the right instinct: a `compile_fail` test that
fails for an unrelated reason (a typo, a moved import) is exactly as vacuous as S1's
crash test was.

## Contradiction in my own slice prompt, resolved correctly

My prompt said both "probes must write only into temp dirs" and "outside paths must be
genuinely outside every permitted region". Those conflict: `/tmp` and `$TMPDIR` **are**
permitted (M7), so a temp-rooted probe reproduces S0 round 1's fatal defect exactly.

The subagent resolved it in favour of the round-1 lesson rather than following my
instruction literally, which is the correct call. Probe scratch lives in
`$HOME/.conductor/probe-<unique>/`, and `ProbeConfig` **refuses** a root inside a
permitted region. The two targets that must sit outside that root by nature are uniquely
named, refused if they already exist, tracked, and deleted. Verified afterwards:
`~/.conductor/` is empty and nothing was left in `$HOME` or `/Users/Shared`.

## Findings worth carrying forward

- **M29 — macOS scans a freshly built binary on first execution: 21.7 s cold vs 3.3 s
  warm.** It made one probe exceed its deadline under parallel test load, and the harness
  correctly reported `broken` / fail-closed rather than a false `Hard`. Fixed at source
  with a payload self-check outside the per-case deadline and a 30 s default. **This will
  bite S3**, which spawns fresh binaries under timeouts for a living.
- **Only measured subjects are cached.** Part 5.1's `containment_probe` has no status
  column, so caching a fail-closed row would turn "could not measure" into a stored
  answer.
- **No TTL was added.** §4.2 keys staleness on versions; a clock-based expiry would be
  invented policy.
